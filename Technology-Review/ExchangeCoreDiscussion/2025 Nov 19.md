\## Key Architecture Discussion

\*\*Technologies Discussed:\*\*

\- \*\*ZeroMQ\*\* - Primary networking solution ("smart sockets" for reliable message buffering and replay)

\## Core Design Patterns

1\. \*\*Event Sourcing + CQRS\*\*

\- All events persisted to Chronicle Queue

\- Incremental snapshots (not full snapshots)

\- State dumped bit-by-bit when less busy

2\. \*\*Message Processing\*\*

\- Batch processing with function signature: \`onMessage(message: ByteArray, isLastInBatch: Boolean): ShouldAck(boolean)\`

\- Only ACK after full successful processing, not just parsing

\- Can block on I/O during batch processing

3\. \*\*High Availability (HA)\*\*

\- Priority-based node selection (no voting - "dictatorship")

\- Master detection via heartbeats (activity every N microseconds)

\- Network replication to multiple AZs before processing

\- Standby takes over if no heartbeats detected

4\. \*\*Testing & Deployment\*\*

\- Run all services in same JVM via IPC (no TCP mocks)

\- Replay events for testing - no special test code needed

\- Supports both single-JVM and multi-JVM microservices patterns

\*\*Key Takeaway:\*\* Use ZeroMQ + Chronicle Queue with deterministic event replay and batching for reliable, testable trading systems.
